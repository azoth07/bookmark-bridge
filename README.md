# 双向书签桥

选择 Chrome 和 Edge 中要合并的文件夹即可自动配对，无需输入同步组名。两端都确认写入完成后，服务会删除整个本机数据目录，包括书签缓存和配对密钥。CMD 持续显示连接、合并、等待确认及清理结果。

## 安装与启动

1. 安装 [Node.js 22 或更新版本](https://nodejs.org/zh-cn)。不需要执行 `npm install`。
2. 双击 `start-bridge.cmd`，保持窗口打开。窗口显示服务地址、配对密钥和实时状态。
3. Chrome 打开 `chrome://extensions`，启用开发者模式，选择「加载已解压的扩展程序」，加载本项目的 `extension` 文件夹。
4. Edge 打开 `edge://extensions`，启用开发人员模式，同样加载 `extension` 文件夹。
5. 在两端扩展设置页填写本次服务的同一份配对密钥，分别选择文件夹，点击「立即同步」。首次只有「配对 1」，无需起名。

点击扩展工具栏图标可重新打开设置页。移动项目目录后需要重新加载扩展。更新代码后，在两端扩展管理页点击「重新加载」，并重启连接服务。

## 按当前收藏夹配置

| 浏览器 | 自动配对编号 | 本地目标文件夹 |
| --- | --- | --- |
| Chrome | 配对 1 | 书签栏 / 已导入 |
| Edge | 配对 1 | 移动收藏夹 |

两个根文件夹名字可以不同。`my`、`my2` 等同名子文件夹递归合并，Chrome 独有的 `my6`、`ea` 和 Edge 独有的 `comic` 会补到另一端。

需要再同步其他互不包含的文件夹时，在两端分别添加「配对 2」，以此类推。同编号相互对应；两端启用的编号必须一致。删除一行不会重排其他编号。不能同时选择父文件夹及其子文件夹。

旧版已有文件夹设置会迁移为自动编号，保留本地目标文件夹和启用状态；旧的手填组名不再使用。若旧版配置过多行，升级后检查两端相同编号对应的文件夹是否正确。

## 同步与清理

一次同步会经过以下状态：

1. **等待另一端**：只收到 Chrome 或 Edge 的内容，数据目录保留。
2. **正在合并 / 等待写入确认**：两端交换并集，浏览器逐条补充缺失的书签和文件夹。
3. **两端确认完成**：两个浏览器都成功写入所有启用配对的最新版本。
4. **数据目录已删除**：删除 `%LOCALAPPDATA%\BookmarkBridge` 整个目录，其中包括 `state.json` 和 `token.txt`。

只上传了内容、只完成一端、两端编号不一致、部分配对失败，均不会触发删除。过期版本的确认也不能提前清理。删除失败时 CMD 会显示错误，不会显示「已删除」。

手动启动的一次同步会继续等待另一端，即使未开启日常自动同步，也会通过后台定时检查完成本次交换。保持两端浏览器和服务运行，通常约一分钟；浏览器休眠或系统节能可能延迟。

双方确认所有配对且数据目录删除成功后，浏览器会显示系统通知。手动点击「立即同步」的每次操作完成后都会提示；自动同步只在新的同步内容完成时提示，定时检查不会反复弹窗。两端浏览器可能分别提示。通知由 Windows 和浏览器管理；如果没有看到弹窗，请检查 Windows 通知设置和专注模式。

**删除的是磁盘目录。** 当前服务进程仍在内存中保留密钥和书签并集，用于继续同步。收到新的变化时会重新生成临时数据目录，待两端再次确认后删除。没有新变化时不会反复把书签缓存写回磁盘。

**服务重启后，已删除的密钥不会恢复。** 新启动会生成新密钥，两端需要重新填写。完整删除目录和跨重启保留配对密钥不能同时成立。

## CMD 状态显示

CMD 显示 Chrome / Edge 接入、各配对上传的书签及文件夹数量、合并版本、等待哪一端确认、全部完成和目录删除成功／失败。

如果服务已经运行，再次双击 `start-bridge.cmd` 会连接现有服务显示实时状态，不再报端口占用错误。此时关闭窗口或按 Ctrl+C 只退出状态查看，后台服务继续运行；窗口会明确说明当前模式。直接启动服务的窗口按 Ctrl+C 会安全停止服务。

日志只显示浏览器名称、自动配对编号、数量和操作结果，不打印收藏标题或网址。配对密钥仅用于启动时配对，请勿公开。

## 合并规则

- 只补充缺少的内容，不删除、不移动、不覆盖已有收藏或标题。
- 同步目标根目录内的内容，不额外套一层根目录。
- 同一路径下子文件夹按完整名称匹配，书签按完整网址匹配。网址参数、片段、协议或结尾斜杠不同，视为不同网址。
- 已有重复书签不清理；已有同名目录会合在一起检查缺失内容，保持原有布局，缺失项补到第一个可写的同名目录。
- 空文件夹也会同步。
- 删除、改名和移动不会传播。当前服务运行期间，内存中的旧并集可能将已删除项补回；改名可能产生新旧两份。若要整理后重新开始，先停止服务并整理两端收藏，再重启服务并重新配对。

## 数据与限制

仅支持同一台电脑上的一份 Chrome 配置与一份 Edge 配置。服务只监听 `127.0.0.1:38473`，数据接口需要密钥，网页来源不能调用同步接口。状态接口仅提供数量和阶段，不提供书签内容或密钥。

扩展只请求书签、扩展本地存储、定时任务、系统通知和本机服务地址访问权限，不读取网页内容，也不直接修改浏览器书签数据库。扩展中的设置保留在各浏览器本地；删除服务数据目录不会删除浏览器收藏或扩展设置。

每次请求最多 8 MiB，每个配对最多 100,000 个节点、64 层目录。企业策略管理的只读收藏夹无法作为写入目标。

## 常见问题

- **等待另一端**：检查两个浏览器是否都打开、使用同一份密钥、选好了本地文件夹并启用了相同编号。两端各点一次「立即同步」。
- **密钥失效**：若上次同步后目录已删除且服务已重启，复制 CMD 中的新密钥到两端。
- **完成后目录还存在**：查看 CMD 是否仍等待某个配对或浏览器确认，或者是否收到新的书签变化。清理遇到不属于应用的文件时会停止并报告，避免误删。
- **文件夹被删除**：刷新文件夹列表并重新选择；其他有效配对仍可继续补齐，但全部完成前不会清理目录。
- **界面仍有同步组名输入框**：两端扩展尚未重新加载。请在扩展管理页重新加载，再打开设置页。
- **没有完成弹窗**：确认两个浏览器都已完成同步且 CMD 显示目录已删除，并检查 Windows 是否允许 Chrome / Edge 发送通知或开启了专注模式。

## 开发

```console
npm start
npm test
```

`extension/` 是 Manifest V3 扩展，`bridge/` 是无第三方依赖的 Node.js 服务。开发时用 `BOOKMARK_BRIDGE_DATA_DIR` 指向专用测试目录、用 `BOOKMARK_BRIDGE_PORT` 指定测试端口。测试目录会在同步完成后整体删除，请不要指向包含其他资料的目录。安装版扩展固定连接端口 38473。
